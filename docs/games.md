# ゲームの zip の配布

学祭の PC に入れるゲームの zip を、部員どうしで受け渡すための仕組みです。部員だけが使います。来場者には見せません。

- 受け取る側: `/games` を開き、合言葉を入れて、ダウンロードします。ログインは要りません。
- 上げる側: `/admin` の「配布ファイル」からアップロードします。GitHub のログイン(Cloudflare Access)が要ります。

トップ(`/`)の左下に、`/games` への小さいリンク(「部員用」)を置いています。来場者が開いても、合言葉が無ければ一覧は見えません。合言葉は、部員に直接伝えます。

## 置き場

R2 のバケット `gakusai2026-games` です。公開の URL は出していません。読み書きは、すべて Worker を通ります。
フォルダは作りません。ファイル名が、そのまま R2 のキーになります。

## 経路

| 経路                                         | 守り方 | 内容                                   |
| -------------------------------------------- | ------ | -------------------------------------- |
| `POST /api/games/login`                      | なし   | 合言葉を確かめて、Cookie を出す        |
| `GET /api/games`                             | Cookie | ファイルの一覧(名前、大きさ、更新時刻) |
| `GET /api/games/dl/:name`                    | Cookie | ファイルを返す。`Range` にも応える     |
| `GET /api/admin/games`                       | Access | ファイルの一覧                         |
| `GET /api/admin/games/dl/:name`              | Access | ファイルを返す(管理画面からの確認用)   |
| `POST /api/admin/games/uploads`              | Access | アップロードを始める                   |
| `PUT /api/admin/games/uploads/:id/parts/:n`  | Access | パートを 1 つ受け取る                  |
| `POST /api/admin/games/uploads/:id/complete` | Access | パートをまとめて、1 つのファイルにする |
| `DELETE /api/admin/games/:name`              | Access | ファイルを消す                         |

Access の設定は [access-setup.md](access-setup.md) にあります。`/api/admin/games/*` は `api/admin/*` に含まれるので、配布のために足した宛先はありません。

## 合言葉

Worker の secret `GAMES_PASSPHRASE` に置きます。

- 合っていれば、合言葉を鍵にした HMAC の値を Cookie(`games_auth`)に入れます。期限は 30 日です。
- 合言葉を変えると、配ってあった Cookie はすべて通らなくなります。
- `GAMES_PASSPHRASE` が無いあいだは、`/api/games/*` はすべて 503 を返します。
- 入力は、同じ送信元から 1 分に 8 回までです。超えると 429 を返します。送信元は、IPv4 ならアドレスごと、IPv6 なら先頭の 64 ビット(/64)ごとに数えます。Workers のレート制限(`GAMES_LOGIN_LIMIT`)で数えていて、`workers.dev` の URL でも独自ドメインでも効きます。
- この数え方はおおよそで、送信元を変えながらの入力は止められません。合言葉は長くします(単語を 4 つ並べる程度)。

## アップロード

Worker が 1 回で受け取れる大きさには上限があります(100MB)。管理画面がファイルを 50MB ずつに切って順に送り、Worker が R2 のマルチパートアップロードとしてまとめます。

- 同じ名前でアップロードすると、置き換わります。差し替えも、この方法で行います。
- 途中で失敗したら、最初から送り直します。続きから送る仕組みはありません。
- 途中で止まったアップロードの残りは、R2 が 7 日後に片付けます(バケットの既定のライフサイクル)。
- ファイル名に `/` と `\` は使えません。長さは 200 文字までです。

## 止め方

学祭が終わったら、次の 2 つを行います。ランキングには影響しません。

1. `GAMES_PASSPHRASE` を消す。`/games` は「配布は止まっています」と出ます。
2. バケットを空にする(管理画面の「配布ファイル」で 1 つずつ消すか、Cloudflare の画面で消す)。

## ローカルで試す

`.dev.vars` に `GAMES_PASSPHRASE` を書いて `vp dev` を動かします。R2 はローカルのもの(`.cloudflare/state`)が使われ、本番のバケットには触りません。
ローカルでは Access の検証を飛ばすので、`/admin` の「配布ファイル」をそのまま使えます。

`src/worker/games.test.ts` は、R2 に触る前で断る経路(合言葉と Access)と、`Range` の計算だけを確かめています。アップロードとダウンロードは、ローカルで実際に動かして確かめます。
