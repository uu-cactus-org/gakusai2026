# 管理画面を Cloudflare Access で守る

作成日: 2026-11-19

管理画面と管理用の API は、Cloudflare Access の GitHub ログインで守ります。この文書は、Access 側の今の設定と、Worker 側でしていることをまとめたものです。

Access の設定は済んでいます(2026-11-19)。本番の `/api/admin/*` を開くとログイン画面に進むところまで確かめました。ログインしたあとに Worker の JWT 検証が通るかは、まだ確かめていません(6 章)。

## 1. 守る範囲

| 経路                 | 用途                       | 守り方                          |
| -------------------- | -------------------------- | ------------------------------- |
| `/admin`、`/admin/*` | 管理画面(まだ作っていない) | Access                          |
| `/api/admin/*`       | 管理用の API               | Access と、Worker での JWT 検証 |
| `POST /api/devices`  | ゲームが PC を登録する     | `GAME_TOKEN`                    |
| `GET /api/devices`   | 表示名を引く               | なし(公開)                      |
| それ以外             | ランキングのページ         | なし(公開)                      |
| プレビューの全経路   | ブランチの確認             | Access                          |

本番で Access をかけるのは `/admin` と `/api/admin` の下だけです。ゲームと中継は機械なので、GitHub のログイン画面を通れません。本番の全体に Access をかけると、ゲームからの登録と中継からの問い合わせが止まります。

## 2. 今の設定

Access のアプリケーションは 1 つだけです。本番の管理用の経路と、プレビューの両方を、同じアプリケーションで守っています。アプリケーションが 1 つなので、AUD タグもポリシーも 1 つです。

**Zero Trust** > **Access controls** > **Applications** で、このアプリケーションの **Edit** を開くと、「宛先」に次の 3 件があります。

| 種類               | 内容                                                     | 入る範囲                           |
| ------------------ | -------------------------------------------------------- | ---------------------------------- |
| パブリックホスト名 | `gakusai2026.uucactus-share.workers.dev` / `admin*`      | 本番の `/admin` と、その下のすべて |
| パブリックホスト名 | `gakusai2026.uucactus-share.workers.dev` / `api/admin/*` | 本番の `/api/admin/` の下のすべて  |
| Workers            | `gakusai2026` / Worker のプレビュー URL                  | プレビューの全経路                 |

ポリシーは `GitHub Organization Members`(許可)です。GitHub の組織のメンバーだけが通ります。

Workers の宛先は、**Workers & Pages** > `gakusai2026` > **Access** タブの「Worker ポリシー」にも「プレビューのみ」と出ます。

## 3. 設定を変えるとき

- **経路を足す**: アプリケーションの **Edit** > 「宛先」> **パブリック ホスト名を追加** で足します。
- **独自ドメインを当てたとき**: 新しいホストで `admin*` と `api/admin/*` を足します。足さないと、新しいホストの管理画面はログインなしで開き、API は Worker が 403 で止めます。
- **Access タブの範囲を「すべてのトラフィック」に変えない**: 本番の全体にかかり、ゲームからの登録と中継からの問い合わせが止まります。
- **Access タブから設定を変えたあと**: パブリックホスト名の 2 件が残っているか確かめます。あの画面が宛先を書き換えるかどうかは、確かめていません。
- **アプリケーションを作り直したとき**: AUD タグが変わります。4 章の値を書き換えてデプロイします。

### 経路の書き方で間違えやすい点

- `admin/*` は `/admin` そのものを含みません。画面の入り口が守られなくなるので、`admin*` と書きます。
- `admin*` は `/administrator` のような経路にも当たります。このサイトにはそういう経路が無いので問題ありません。
- `api/admin/*` を登録し忘れると、画面だけ守られて API が外に出ます。この場合も Worker が 403 を返すので中身は守られますが(5 章)、管理画面から API を呼べなくなります。

## 4. Worker に値を設定する

Worker が JWT を確かめるために、次の 2 つの値が要ります。どちらも秘密ではないので、`cloudflare.config.ts` に直接書いてコミットします。

| 定数                 | 値                                        | 調べる場所                                                                                     |
| -------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `ACCESS_TEAM_DOMAIN` | `https://<チーム名>.cloudflareaccess.com` | **Zero Trust** > **Settings** > **Team name and domain**                                       |
| `ACCESS_AUD`         | アプリケーションの AUD タグ               | **Access controls** > **Applications** > アプリケーションの **Edit** > **Additional settings** |

- `ACCESS_TEAM_DOMAIN` は `https://` を付け、末尾に `/` を付けません。JWT の発行者(`iss`)と文字どおり比べるためです。
- AUD タグは、アプリケーションを消して作り直すと変わります。作り直したら、こちらも書き換えてデプロイします。

どちらも記入済みです。値を変えたらデプロイします。

```sh
vp run deploy
```

## 5. Worker がしていること

Access はログインを Worker の手前で済ませ、通したリクエストに `Cf-Access-Jwt-Assertion` ヘッダーで JWT を付けます。Worker(`src/worker/auth.ts` の `requireAccess`)は、`/api/admin/*` のすべてのリクエストでこの JWT を確かめます。

- 署名を、`<ACCESS_TEAM_DOMAIN>/cdn-cgi/access/certs` の公開鍵で確かめる。
- 発行者(`iss`)が `ACCESS_TEAM_DOMAIN` と同じか確かめる。
- 宛先(`aud`)に `ACCESS_AUD` が入っているか確かめる。
- 期限が切れていないか確かめる。

| 状況                                         | 応答 |
| -------------------------------------------- | ---- |
| `ACCESS_TEAM_DOMAIN` か `ACCESS_AUD` が空    | 503  |
| ヘッダーが無い(Access を通っていない)        | 403  |
| JWT が無効(署名、発行者、宛先、期限のどれか) | 403  |

Access の設定が外れたり、経路を間違えたりしても、この検証があるので管理用の API は開きません。

`ctx.access` は使っていません。静的アセットを持つ Worker では、`ctx.access` が Worker に渡らないためです。

### ローカル開発

ローカルには Access が無いので、`vp dev` のときだけ検証を飛ばします。`cloudflare.config.ts` が、モードが `development` のときに限って `ACCESS_DEV_BYPASS` を `true` にします。`vp build` と `cf deploy` は `production` で動くので、デプロイしたものでは必ず `false` です。

`cf deploy --mode development` のようにモードを指定してデプロイすると、検証が外れた状態で公開されます。モードは指定しません。

## 6. 動作を確かめる

デプロイしたあと、ブラウザーで次の順に確かめます。

1. シークレットウィンドウで `https://<ホスト>/api/admin/me` を開く。GitHub のログインに進み、許可したアカウントでログインすると `{"email":"..."}` が出る。
2. 許可していないアカウントでログインすると、Access の拒否画面が出る。
3. `https://<ホスト>/api/devices` は、ログインなしで開ける。

ログイン画面が出ずに 403 が返る場合は、その経路が Access に登録されていません。2 章の表を見直します。

## 7. プレビュー

プレビューの URL(`<プレビュー名>-gakusai2026.uucactus-share.workers.dev`)は、2 章のアプリケーションの Workers の宛先で、全経路がログイン必須になっています。

- ランキングのページも、`/api/devices` も、ログインが要ります。ゲームや中継をプレビューの URL に向けて試すことはできません。
- 本番と同じアプリケーションを通るので、AUD タグも同じです。Worker の設定をプレビュー用に分ける必要はありません。

### データ

プレビューは本番と同じ D1 につながります。プレビューで登録した PC は本番の連番を消費し、表示名の変更も本番に反映されます。

プレビューは本番の secret を引き継ぎません。`GAME_TOKEN` をプレビューにも設定するまで、プレビューの `POST /api/devices` は 503 を返します。
