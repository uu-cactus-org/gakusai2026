# PC の登録と表示名

ランキングは、会場の PC を ID で見分け、`PC1`、`PC2` のような表示名を付けて管理します。表示名は全ゲーム共通です。ゲームと、WaterShooting の中継(water-shooting-web)の管理画面が、この API を使います。

本番の URL は `https://gakusai2026.uucactus-share.workers.dev` です。

## PC の ID

- Unity の `SystemInfo.deviceUniqueIdentifier` をそのまま使います。同じ PC なら、Unity 製のどのゲームからも同じ値になります。
- 受け付けるのは 1〜128 文字の文字列です。形は決めていません。環境によって値の形が変わりうるので、形が合わずに当日の登録が落ちることを避けています。
- ID を知っている人は、その PC のふりができます。本人の証明にはなりません。

## 表示名

- 初めて登録された PC に、そのときの登録数の次の番号を付けます(登録済みが 2 台なら `PC3`)。`PC` と数字の間に空白は入れません。
- 数えるのと登録するのを 1 つの SQL で行うので、同時に登録が来ても番号は重なりません。
- 表示名はあとから管理用の API で変えられます。
- 行を消すと登録数が減るので、次の PC の番号が既存の表示名と重なることがあります。消さずに運用します。

## API

| 経路                             | 用途           | 守り方            |
| -------------------------------- | -------------- | ----------------- |
| `POST /api/devices`              | PC を登録する  | `GAME_TOKEN`      |
| `GET /api/devices?ids=<ID>,<ID>` | 表示名を引く   | なし              |
| `GET /api/devices`               | 登録済みの全件 | なし              |
| `PATCH /api/admin/devices/:id`   | 表示名を変える | Cloudflare Access |

### `POST /api/devices`

ゲームが呼びます。`Authorization: Bearer <GAME_TOKEN>` を付けます。

```json
{ "id": "<PC の ID>" }
```

応答は `{ "id": "...", "name": "PC3" }` です。新しく登録したときは 201、登録済みのときは 200 で今の表示名を返します。何度呼んでもかまいません。

### `GET /api/devices`

応答は `{ "devices": [{ "id": "...", "name": "PC3" }] }` です。

- `ids` を付けると、聞かれた順に返します。1 回に 100 件までです。
- 登録されていない ID は、応答から省きます。この API は登録をしません。
- ID にカンマが入っていると、`ids` では引けません。

### `PATCH /api/admin/devices/:id`

本文は `{ "name": "受付の PC" }` です。表示名は 1〜32 文字です。Access の設定は [access-setup.md](access-setup.md) にあります。

## 鍵

`GAME_TOKEN` は、ゲームのビルドに埋め込みます。使うのは学祭当日だけです。配布するビルドからは鍵を消し、当日が終わったら API も閉じます。

## 決めていないこと

- **スコアの API**: まだ作っていません。ゲームごとに専用の形で作ります。
- **スコア送信のときの登録**: スコアを送ってきた PC が未登録だった場合に、その場で登録するかどうか。
